# 项目参考

## 核心文件

- `window_capture.py`
  - 主 GUI
  - DWM 预览、采样预览、Debug 放大镜
  - 窗口锚定、后台保活、恢复原位、任务栏图标切换、设置分辨率
- `script_action.py`
  - `WindowAutomation` 动作库
  - 后台点击、拖动、按键、模板识别
  - 供 GUI 与自定义脚本复用
- `templates/`
  - 模板识别素材
  - 文件名通常直接用于 `find_image()` / `click_image()`
- `README.md`
  - 环境说明
  - 推荐工作流
  - 历史变更日志

## 项目惯例

- 这个项目长期围绕“后台预览 + 后台自动化”迭代，优先修正现有链路，不轻易引入全新架构。
- 用户在意可调试性，所以日志、状态栏提示、README 说明都很重要。
- 用户已多次要求：每次明显功能改动，都要把摘要写进 `README.md`。
- 对窗口做了位置、尺寸、样式修改后，要确保支持手动恢复和关闭时自动恢复。

## 常见风险点

- 管理员/UIPI：目标程序提权时，普通权限下的输入注入和窗口管理可能失败。
- DWM 预览：能看到的是合成器持有的帧，不等于目标程序继续渲染。
- 采样预览：属于 `PrintWindow` / GDI 链路，不等于 GPU 直出。
- 游戏窗口：可能是独占全屏、自管理窗口或自绘输入，不保证标准 Win32 行为完全适配。
- 尺寸调整：用户通常说“分辨率”时，实际更关心客户区尺寸，而非外框尺寸。

## 默认验证方式

- 改完 Python 文件后运行 `python -m py_compile`
- 读取对应文件的 lints
- 在最终说明里标明哪些行为已静态验证，哪些仍需用户在真实目标程序中验证
