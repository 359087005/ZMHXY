# 项目规则

- 这是一个 Windows 专用 Python 项目，默认沿用 `tkinter` + `ctypes` + Win32 API 的实现方向；除非用户明确要求，不主动引入重型框架或大规模重构。
- 模块职责保持清晰：
  - `window_capture.py` 负责 GUI、预览链路、窗口状态管理、调试入口。
  - `script_action.py` 负责可复用自动化动作、识别接口和脚本侧 API。
  - `templates/` 只放模板识别素材与说明。
  - `README.md` 维护环境说明、使用方式和变更日志。
- 涉及窗口位置、尺寸、样式、任务栏图标、后台保活时，优先保证“可恢复”，避免目标窗口在工具退出后残留异常状态。
- 涉及输入注入、窗口管理、预览抓取时，保留可诊断日志，优先输出 `hwnd`、`pid`、Win32 返回值和错误信息。
- 鼠标/键盘自动化优先维持单一稳定主链路；不要无故堆叠多套重复策略，除非用户明确要求增加回退方案。
- 新增自动化能力时，优先先落到 `script_action.py` 的 `WindowAutomation` 方法，再由 GUI 或脚本入口调用。
- 任何会改变用户工作流、按钮行为、参数含义、模板使用方式的改动，都要同步更新 `README.md`。
- 这个项目习惯持续维护 `README.md` 的变更日志；每次功能性修改后，补一条简短版本记录。
- 提交代码前的默认校验：
  - 对受影响的 Python 文件运行 `python -m py_compile`
  - 检查修改文件的 lints
  - 明确说明无法在当前环境 fully 验证的 Windows / 游戏特性风险

# 示例

- 新增一个 GUI 按钮时，同时补 `README.md` 的功能说明和变更日志。
- 修改后台点击或窗口管理逻辑时，确认“恢复原位”与自动恢复流程仍然成立。
